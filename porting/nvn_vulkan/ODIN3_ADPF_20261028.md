# Odin3 ADPF 对照结果：保留默认关闭

## 结论

共享宿主性能提示设施已实现，Android 适配器使用公开 NDK Hint API，Mac 报告不支持。
**本轮未通过 S5 验收，不提升为默认配置。** 同 PID 四窗 OFF/ON 合并
29.4370 → 30.0086 FPS（+1.942%），低于预先规定的 +2%。五分钟持续验证在
167.44 秒后因 BOTW 进程退出中断；后续 Litep/Perfetto/SF 对照没有启动，
不能声称实际频率、翻译 CPU 或 p99 已改善。

[Profiler O2 修复](ODIN3_PROFILER_O2_20261028.md)已独立通过，不受此实验未验收影响。

## 实现与边界

设计见 [S5 宿主工作时长提示](ODIN3_ADPF_DESIGN_20261028.md)。

- `renderer_hint on|off|status` 默认 OFF，不持久化到游戏设置。
- 两个实际工作 TID 各有一个 Session；本轮翻译 TID2735、呈现 TID2940。
  目标16,666,667 ns，翻译复用已有 elapsed，呈现排除 Acquire、QueuePresent 和复制 fence。
- 一个宿主 worker 独占平台 API，每通道只保留一个待处理样本；调用后端前释放独立队列锁。
  不从持有 Vulkan 前端/引擎锁的线程同步调用 Binder。
- generation/applied 显示请求和生效的区别；OFF 等 Session 关闭后才开始对照。
  TID 变化重建 Session，后端失败不逐帧重试；退出关闭自身 Session。
- Vulkan 钩子、队列和策略共用；平台差异只在 Hint API 适配器。
  未改 NCORE=3、Guest 核掩码、优先级、抢占、亲和性、频率或同步语义。

## 中断与证据缺口

ON长窗口原定300秒，保留164个状态样本、5023次成功Present、167.4406秒，
部分窗口29.9987 FPS。六次热状态采样均为0，实时HAL CPU温度范围54.6–61.1℃，
skin 44.40–44.78℃。不用系统缓存的旧温度冒充当前温度，也不将此不足三分钟的
窗口称作五分钟稳定性通过。

系统退出记录：2026-10-28 18:54:53.017，PID2411，EXIT_SELF/status0；
随后只读检查发现前台是 shadPS4 MainActivity。没有新的 BOTW 崩溃证据，
也没有证明是谁或哪条路径触发了退出。本轮未操作其他应用，未自动重启重试。

原始 `abab-live/result.json` 保留 failed 和 cleanup_error：PID已经不存在，无法
向旧进程恢复运行时开关。进程局部 Hint/采样状态随退出结束，启动属性已经恢复，
新进程仍按默认OFF启动。`summary.json` 单独汇总完成的四窗和中断的长窗口，
不改写原始失败记录。

A/B后的独立联合采集 helper 在看到 failed 时退出，尚未开始任何采集。
所以本轮**缺少** Hint ON/OFF 实际频率、翻译CPU、SurfaceFlinger与帧时p99对照；
不能用约1秒一次的renderer状态轮询计算逐帧分位数。此前O2版的联合采集只能作为
选择ADPF实验的依据，不能替代本APK/开关的对照。

修正测试脚本：后续长窗口无论成功或异常，都会保存样本数、观察到的时长和
`complete/interrupted` 状态，原始jsonl持续刷盘。新增中断前缀与最终检查失败测试；
包含原有稳定性用例共5个Python测试通过。

1. 保留O2修复；ADPF保持默认OFF。S5还缺上述证据，不宣称阶段完成。

   继续记录运行频率，避免把调频变化当作代码降本；不依据未闭合的M↔R因果链启用S2。
